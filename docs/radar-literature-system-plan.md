# 雷达信号处理文献收集、整理、在线查询与归档系统规划

## 1. 项目目标

面向课题组围绕 3~4 个研究方向开展的文献整理工作，建立一个可持续运行的“文献采集—清洗—标注—检索—归档—复用”系统。系统应同时满足以下目标：

1. **集中收集**：统一接入 arXiv、IEEE Xplore、Google Scholar、Crossref、期刊官网和组内已有 PDF。
2. **结构化整理**：将论文的题目、作者、年份、关键词、研究方向、方法标签、数据集、代码链接等信息标准化存储。
3. **在线查阅**：支持按研究方向、问题类型、方法关键词、年份、作者、会议/期刊进行搜索和筛选。
4. **知识沉淀**：支持课题组成员为每篇论文补充摘要、方法理解、优缺点、可复现性评价和与本组工作的关联。
5. **可归档可追踪**：保留原始 PDF、解析文本、笔记、标签修改记录和任务状态，便于长期维护。
6. **服务科研任务**：能够快速回答“某方向最新工作有哪些”“某算法在哪些雷达体制下使用过”“有哪些文章用了同一数据集/评价指标”等问题。

---

## 2. 推荐采用的总体思路

建议将系统拆成四层：

1. **文献源采集层**：负责从公开数据库、手工上传和已有网盘资料中采集元数据与 PDF。
2. **知识整理层**：负责去重、打标签、补摘要、生成结构化卡片。
3. **检索与问答层**：负责全文搜索、标签筛选、语义检索和基于文献库的问答。
4. **归档与协作层**：负责版本管理、权限控制、分工审核和备份。

如果希望快速落地，我建议优先采用“**数据库 + 对象存储 + 向量检索 + Web 前端**”的组合：

- **数据库**：PostgreSQL，用于保存论文元数据、标签、笔记、任务状态。
- **对象存储/文件存储**：本地 NAS、S3 兼容存储或服务器磁盘，用于保存 PDF、封面图、附件。
- **搜索引擎**：先用 PostgreSQL 全文检索，后续需要增强时再接入 OpenSearch/Elasticsearch。
- **向量检索**：pgvector 或 Milvus，用于语义搜索“与某论文相似的工作”。
- **后端服务**：Python（FastAPI）最适合和论文处理、NLP、爬取脚本联动。
- **前端**：内部使用可先做轻量页面，后续再扩展成完整门户。

这个方案的好处是：**实现成本适中、可控性强、适合实验室内部长期维护**。

## 3. 面向课题组的业务拆解

### 3.1 研究对象组织方式

建议先把课题组的 3~4 个方向定义成一级主题，例如：

- 雷达目标检测
- 雷达成像与重建
- 参数估计与波形设计
- 智能感知/深度学习雷达处理

在一级主题下再建立二级标签：

- **任务标签**：检测、分类、跟踪、DOA 估计、STAP、成像、分割、波形优化等。
- **体制标签**：MIMO 雷达、相控阵、SAR、ISAR、毫米波 FMCW、被动雷达、多基地等。
- **方法标签**：稀疏表示、压缩感知、贝叶斯方法、图模型、Transformer、扩散模型、强化学习等。
- **实验标签**：仿真、公开数据集、实测数据、硬件在环。
- **成熟度标签**：综述、理论、算法、系统、开源可复现。

这样做的核心目的，是把“**按论文来源存储**”转变为“**按科研问题组织知识**”。

### 3.2 一篇论文的标准处理单元

建议为每篇论文建立统一的“文献卡片”，至少包含：

- 基础信息：标题、作者、年份、期刊/会议、DOI、URL。
- 分类信息：方向、任务、体制、方法、数据集、关键词。
- 内容摘要：问题定义、核心方法、主要贡献、实验设置、主要结论。
- 评价信息：优点、局限、适用条件、是否值得精读。
- 关联信息：相关论文、被谁引用、是否有代码、是否可复现。
- 组内信息：谁阅读、阅读日期、讨论结论、与本组课题的关联。

如果你们后续希望做在线问答，这种结构化卡片会极大提高检索质量。

## 4. 系统功能设计

## 4.1 文献采集模块

### 输入来源

建议至少接入以下三类来源：

1. **自动采集源**
   - arXiv（预印本）
   - Crossref（DOI 与基础元数据）
   - OpenAlex（学术关系、引用信息较好）
   - Semantic Scholar（相似论文、引用网络）

2. **半自动采集源**
   - IEEE Xplore 检索结果导出
   - Google Scholar 手工导出
   - 期刊官网链接导入

3. **手工导入源**
   - 导师/同门已有 PDF
   - 组内共享网盘
   - Zotero/BibTeX 导出文件

### 采集策略

建议按“**主题词模板**”定期检索，而不是完全依赖人工搜索。每个方向建立检索模板，例如：

- `radar signal processing + DOA estimation`
- `MIMO radar + sparse recovery`
- `FMCW radar + micro-Doppler + classification`
- `SAR imaging + deep learning`

每周或每两周运行一次，抓取新增结果并做去重。

### 去重规则

去重建议按优先级进行：

1. DOI 完全一致；
2. 标题归一化后完全一致；
3. 标题相似度高且作者/年份接近；
4. arXiv 与正式发表版本建立“版本关联”，不要简单删除。

---

## 4.2 元数据与标签模块

### 建议数据表

至少包含以下实体：

- `papers`：论文主表
- `authors`：作者表
- `paper_authors`：论文-作者关联表
- `venues`：期刊/会议表
- `tags`：标签表
- `paper_tags`：论文-标签关联表
- `notes`：阅读笔记表
- `attachments`：PDF、补充材料、代码快照
- `collections`：专题文献集
- `tasks`：待精读、待复现、待汇报等任务

### `papers` 表推荐字段

- `id`
- `title`
- `title_normalized`
- `abstract`
- `year`
- `venue_id`
- `doi`
- `arxiv_id`
- `source_url`
- `pdf_path`
- `full_text_path`
- `language`
- `paper_type`（journal/conference/preprint/thesis/report）
- `direction_primary`
- `read_status`
- `reproducibility_level`
- `priority_score`
- `created_at`
- `updated_at`

### 标签体系建议

标签不要一开始就放得太细，建议采用三级体系：

- **一级**：研究方向
- **二级**：任务/体制/方法/数据
- **三级**：细化关键词

例如：

- `方向/雷达成像`
- `任务/目标检测`
- `体制/FMCW`
- `方法/压缩感知`
- `方法/Transformer`
- `数据/KASSPER`
- `评价指标/PSNR`

## 4.3 文本解析与知识抽取模块

这一层非常关键，因为后续在线查询质量取决于这里做得是否扎实。

### 建议处理流程

1. 获取 PDF。
2. 提取正文文本。
3. 解析章节标题、摘要、关键词、参考文献。
4. 用规则 + 大模型生成结构化摘要。
5. 抽取关键字段：
   - 雷达体制
   - 任务类型
   - 方法名称
   - 数据集/仿真条件
   - 指标
   - 是否有开源代码
6. 将长文切片，写入向量库用于语义检索。

### 为什么不建议只存 PDF

如果只归档 PDF，后面你们会遇到三个问题：

- 很难按细粒度问题搜索；
- 很难快速比较多篇论文；
- 很难支撑“在线问答”和“自动综述生成”。

所以建议至少保留三种文本产物：

- 原始 PDF
- 清洗后的全文文本
- 结构化文献卡片

## 4.4 在线查询模块

在线查询建议分成三种模式：

### 模式 A：结构化检索

适合回答：

- 2021 年后 FMCW 雷达目标分类论文有哪些？
- 使用 Transformer 做 SAR 成像/解译的工作有哪些？
- 同时使用稀疏恢复和 MIMO 雷达的论文有哪些？

依赖条件：标签体系和元数据质量较高。

### 模式 B：全文检索

适合回答：

- 哪些论文提到 “micro-Doppler signature”？
- 哪些论文正文中对比了 MUSIC 和 ESPRIT？
- 哪些文章提到了特定公开数据集？

依赖条件：完成 PDF 文本解析和索引。

### 模式 C：语义检索/问答

适合回答：

- 找几篇和某篇文章思想最接近的工作。
- 帮我总结某个方向近五年的研究脉络。
- 某个方法在哪类雷达场景下效果更好？

依赖条件：向量检索 + 文献卡片 + 引用原文片段。

### 查询结果页面建议显示

每条结果建议展示：

- 标题、作者、年份、会议/期刊
- 方向标签、方法标签、体制标签
- 结构化摘要
- 关键贡献 3 条
- 与当前查询的相关性原因
- PDF 链接、外部链接、代码链接
- 组内笔记和负责人

---

## 4.5 协作与归档模块

建议加入以下协作状态：

- `new`：新采集未处理
- `screened`：已初筛
- `tagged`：已打标签
- `summarized`：已写摘要
- `reviewed`：已审核
- `archived`：已归档
- `to_read` / `to_reproduce` / `to_report`

每篇论文最好支持：

- 指派责任人
- 设置截止时间
- 记录阅读会议讨论结论
- 标记是否进入组会汇报池

归档时建议固定文件命名规则：

`年份_第一作者_关键词缩写_题目短名.pdf`

例如：

`2024_Wang_MIMO_DOA_sparse_bayesian.pdf`

这样既便于人工浏览，也便于后端脚本处理。

## 5. 推荐的技术实现方案

## 5.1 第一阶段：最小可用系统（4~6 周）

目标：先把“能持续收集、能查、能归档”做起来。

### 技术栈建议

- 后端：FastAPI
- 数据库：PostgreSQL
- 向量扩展：pgvector
- 文件存储：本地磁盘/NAS
- 任务调度：cron 或 Celery
- 文本解析：PyMuPDF、GROBID（可后续接入）
- 前端：简单管理后台即可

### 必做功能

1. 文献手工导入 + BibTeX 导入
2. PDF 上传与存储
3. 元数据编辑页面
4. 标签管理
5. 按标签/年份/关键词搜索
6. 阅读笔记录入
7. 导出专题文献清单

### 暂时可以不做

- 复杂权限体系
- 自动引用图谱可视化
- 高级推荐算法
- 多模型自动摘要对比

这一步的原则是：**先让组里愿意用起来**。

---

## 5.2 第二阶段：半自动智能整理（6~10 周）

目标：减少人工录入成本，提高检索质量。

### 新增功能

1. 自动从 DOI/URL 拉取元数据
2. 自动提取摘要与关键词
3. 自动推荐标签
4. 自动识别论文中提到的数据集/方法名
5. 相似论文推荐
6. 主题周报：本周新增哪些相关论文

### 适合使用大模型的环节

- 生成结构化摘要
- 从全文提取“方法—实验—结论”卡片
- 给论文推荐方向标签与方法标签
- 回答组内基于文献库的自然语言问题

但要注意，大模型**不能替代文献数据库本身**，而应作为“标注助手”和“问答入口”。

---

## 5.3 第三阶段：面向科研产出的知识系统（长期）

目标：让系统直接服务于开题、综述和论文写作。

### 可以扩展的能力

1. 自动生成某主题的文献综述大纲
2. 自动形成“方法演化路线图”
3. 自动比对不同论文的实验设置
4. 自动输出开题报告参考文献包
5. 支持“和我们自己的实验结果”做关联记录

这一阶段，系统就不再只是“文献仓库”，而是“课题知识库”。

## 6. 团队工作流建议

建议按以下流程运行：

### 角色分工

- **系统维护者 1 人**：维护采集脚本、数据库、服务。
- **方向负责人 3~4 人**：分别负责一个研究方向的标签规范和质量审核。
- **学生成员若干**：负责初筛、摘要填写、精读记录。

### 周期性工作安排

#### 每周

- 自动采集新增文献
- 各方向负责人完成初筛
- 将高优先级论文加入“待精读”列表

#### 每两周

- 统一审核新增标签
- 清理重复条目
- 输出新增文献简报

#### 每月

- 形成每个方向的“重点论文清单”
- 更新方向综述框架
- 盘点哪些论文值得复现/跟进

## 7. 面向雷达信号处理的专用字段建议

由于你们是雷达信号处理课题组，建议比通用文献系统多加一些专业字段：

- 雷达体制：FMCW、脉冲、多基地、MIMO、SAR、ISAR、被动雷达等
- 工作场景：车载、低空监视、海杂波、人体感知、遥感、电子战等
- 信号域：时域、频域、时频域、距离-多普勒域、角度域、图像域
- 处理层级：回波建模、预处理、检测、估计、跟踪、识别、成像、融合
- 方法范式：模型驱动、数据驱动、模型数据融合
- 数据来源：仿真、公开数据、实测、半实物平台
- 核心假设：稀疏性、低秩、平稳性、高斯噪声、独立同分布等
- 指标：检测率、虚警率、角度估计误差、成像分辨率、PSNR、SSIM、运行时

这些字段会显著提升你们后续做专题比较和综述写作的效率。

## 8. 文献卡片模板建议

建议每篇论文在系统中至少生成以下卡片内容：

### A. 速览卡

- 一句话问题定义
- 一句话方法概述
- 一句话结论
- 是否值得精读：高/中/低

### B. 精读卡

- 研究问题是什么？
- 现有方法缺点是什么？
- 该文核心思想是什么？
- 数学模型或网络结构是什么？
- 实验设计是否合理？
- 主要结果是什么？
- 最大局限是什么？
- 与我们课题的结合点是什么？

### C. 复现卡

- 是否公开代码？
- 是否公开数据？
- 复现难度：低/中/高
- 关键超参数
- 潜在复现风险

## 10. 我建议你们现在就做的三件事

如果希望最快启动，我建议立刻做这三件事：

1. **先定义标签体系和文献卡片模板**。这是整个系统的核心，不先定好，后续数据会越来越乱。
2. **先导入课题组已有 100~300 篇核心论文**。用已有文献建立种子库，比直接全网抓取更稳。
3. **先做内部检索与归档，不急着追求“全自动智能问答”**。因为真正决定效果的是底层数据质量。
